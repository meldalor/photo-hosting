# Функциональные требования MVP
## Основные модули системы

### Модуль "Регистрация и авторизация"
1. Система должна предоставлять форму регистрации с полями Email и Пароль
2. Система должна проверять уникальность email в IndexedDB
3. Система должна хэшировать пароль с помощью Web Crypto API перед сохранением
4. Система должна предоставлять форму авторизации с проверкой учетных данных
5. Система должна сохранять сессию в localStorage и SessionContext

### Модуль "Загрузка изображений"
1. Система должна предоставлять форму загрузки файлов с валидацией типа и размера
2. Система должна отображать предпросмотр выбранного изображения
3. Система должна сохранять изображение как Blob в IndexedDB с привязкой к userId
4. Система должна валидировать файлы (только изображения, максимум 10MB)

### Модуль "Галерея изображений"
1. Система должна отображать все изображения текущего пользователя в адаптивной сетке
2. Система должна преобразовывать Blob в URL для отображения
3. Система должна показывать метаданные для каждого изображения (имя файла, дата, автор)
4. Система должна предоставлять возможность удаления изображений

### Модуль "Навигация"
1. Система должна предоставлять защищенные маршруты с проверкой авторизации
2. Система должна автоматически перенаправлять неавторизованных пользователей на /login
3. Система должна отображать Header с навигацией и кнопкой выхода


## Технические требования
- Два независимых проекта: frontend + ui-библиотека
- ES6 modules (import/export)
- TypeScript
- Запрещены: require, module.exports, var


## Use Case: Регистрация и первая загрузка изображения
### Участники
Новый пользователь, Система аутентификации, Система управления изображениями
### Предусловия
- Пользователь открыл приложение
- Пользователь не имеет учетной записи
### Основной сценарий
1. Пользователь переходит на страницу /register
2. Система отображает форму регистрации
3. Пользователь вводит email и пароль
4. Пользователь нажимает кнопку "Зарегистрироваться"
5. Система валидирует данные и проверяет уникальность email
6. Система хэширует пароль и сохраняет пользователя в IndexedDB
7. Система автоматически авторизует пользователя
8. Система перенаправляет на /gallery
9. Система показывает сообщение "У вас пока нет изображений"
10. Пользователь нажимает "Загрузить изображение"
11. Система перенаправляет на /upload
12. Пользователь выбирает файл изображения
13. Система отображает предпросмотр
14. Пользователь нажимает "Загрузить"
15. Система сохраняет изображение в IndexedDB
16. Система перенаправляет в галерею
17. Система отображает загруженное изображение
### Результат
Пользователь зарегистрирован и загрузил первое изображение
### Альтернативный сценарий
1. Система обнаруживает, что email уже зарегистрирован
2. Система показывает ошибку "Пользователь с таким email уже существует"
3. Пользователь исправляет email
4. Возврат к шагу 4


## Use Case: Просмотр и удаление изображений
### Участники
Авторизованный пользователь, Система управления изображениями
### Предусловия
- Пользователь авторизован
- В галерее есть загруженные изображения
### Основной сценарий
1. Пользователь переходит на страницу /gallery
2. Система загружает все изображения пользователя из IndexedDB
3. Система отображает изображения в адаптивной сетке Gallery
4. Пользователь просматривает изображения
5. Пользователь нажимает кнопку "Удалить" на одном из изображений
6. Система показывает диалог подтверждения
7. Пользователь подтверждает удаление
8. Система удаляет изображение из IndexedDB
9. Система обновляет галерею
10. Система показывает уведомление "Изображение удалено"
### Результат
Пользователь просмотрел галерею и удалил ненужное изображение
### Альтернативный сценарий
1. Пользователь нажимает "Отмена" в диалоге подтверждения
2. Система закрывает диалог
3. Изображение остается в галерее
